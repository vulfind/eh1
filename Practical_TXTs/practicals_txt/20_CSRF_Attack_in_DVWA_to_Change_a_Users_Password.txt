Practical No. 20

CSRF Attack in DVWA to Change a User's Password
Aim: To demonstrate a Cross-Site Request Forgery attack that silently changes a logged-in user's DVWA password.
Tools / Requirements: DVWA (Low security), attacker-hosted HTML page
Procedure:
  1.   Open the CSRF module at Low security and observe the password-change request pattern, e.g. GET
       /dvwa/vulnerabilities/csrf/?password_new=NEW&password_conf=NEW&Change=Change#
  2.   Craft a malicious HTML page containing an auto-submitting form or <img> tag pointing to that exact URL with an
       attacker-chosen password.
  3.   Host the page on the attacker machine (e.g. via python3 -m http.server).
  4.   While the victim is logged into DVWA in the same browser, have them open the attacker's page (simulated by
       browsing to it in the same session).
  5.   Confirm the victim's DVWA password has been changed without their knowledge, proving the CSRF vulnerability.
  6.   Note the mitigation: anti-CSRF tokens, SameSite cookies, re-authentication for sensitive actions.
